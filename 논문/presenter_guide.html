프로젝트 한 줄 요약
사용자의 수분·단백질·운동 데이터를 수집하고, K-Means 클러스터링으로 행동 유형을 분류한 뒤,

왜 만들었나 (서론 핵심)

기존 헬스케어 앱들은 데이터를 기록하고 시각화하는 데 그침.
사용자 개개인의 신체 조건이나 운동 습관 변화를 반영한 능동적인 맞춤형 코칭이 없음.

↓
🤖

↓
💬
LLM(GPT)이 그룹 데이터 기반으로 개인화 코칭 생성

4
핵심 기술 — K-Means 클러스터링

왜 클러스터링인가?
실제 사용자 데이터가 충분히 쌓이기 전에도 즉각적인 맞춤형 코칭이 필요함
→ 가상 데이터 300명 × 7일 = 2,100건으로 사전 학습된 모델 사용

입력 변수설명비고
water_ml일일 수분 섭취량7일 평균
protein_g일일 단백질 섭취량7일 평균
strength_min근력 운동 시간7일 평균
cardio_min유산소 운동 시간7일 평균

※ 키·몸무게·나이는 제외 — 체형 편향 방지, 행동 패턴 분류가 목적

K=4 선택 근거
Elbow Method + Silhouette / Davies-Bouldin / Calinski-Harabasz / Inertia 감소율 4가지 지표로 결정.
K=4가 군집 해석 가능성 + 분리도 최적.

🏃 저수분·유산소 집중형 (83명)
유산소는 많이 하지만 수분 섭취 부족. 수분 보충 권고.
🏋️ 저수분·근력 집중형 (57명)
근력 운동량 가장 많지만 전체 군집 중 수분 최저. 수분·단백질 보충 필요.
🚴 저단백·유산소 집중형 (73명)
유산소 중심 생활, 단백질 섭취가 낮음. 단백질 80g 이상 섭취 권고.
💪 고수분·고단백형 (87명)
수분·단백질 균형 잡힘. 현재 패턴 유지·일관성 강조 코칭.

유사 사용자 매칭 (클러스터링과 별개 프로세스)

구분기준역할
클러스터링행동 패턴 (수분/단백질/운동)내 행동 유형 분류
유사 사용자 매칭신체 조건 (키·몸무게·나이 절대차 합산)비교 대상 5명 선정

두 결과를 결합 → "나와 체형이 비슷한 사람들 대비 내 생활패턴이 어떻게 다른가" 상대적 비교 가능

5
AI 챗봇 동작 방식 (Function Calling)

GPT에게 단순히 질문하는 게 아니라 Function Calling 방식으로 동작.

사용자: "오늘 닭가슴살 200g 먹었어"
→ GPT가 의도 파악 → save_record_data 함수 호출 결정
→ FastAPI가 DB에 단백질 46g 저장
→ GPT가 저장 결과 받아서 자연어 응답 생성
→ 앱에 SaveCard UI + 코칭 텍스트 출력
함수명트리거 예시결과 UI
save_record_data"닭가슴살 200g 먹었어", "헬스 1시간 했어"SaveCard + DB 저장
get_today_status"오늘 현황", "오늘 얼마나 했어?"StatusCard (오늘 달성률)
get_coaching_advice"코칭해줘", "이번 주 어때?"텍스트 코칭
get_coaching_report"리포트 분석해줘"리포트 카드 6종
recommend_food"단백질 채우려면 뭐 먹어?"FoodCard (식약처 DB 연동)

리포트 카드 6종 상세 설명

"리포트 분석해줘" 입력 시 아래 6개 카드가 순서대로 출력됨

① 종합 점수
점수 원형 링(최대 100점), 행동 유형(클러스터명), 수분/단백질/운동 트렌드(증가/감소/유지)
② 수분 섭취
나의 평균 vs 목표 달성률, 그룹 평균 비교, 권장 기준 출처 명시
③ 단백질 섭취
동일 구조, 체중×1.2~1.7g/kg 기준, 보건복지부 식생활 지침 출처
④ 운동량
근력/유산소 분리 분석, 각각 목표 달성률, WHO 권장 기준 출처
⑤ 유사 사용자 비교
나 vs 그룹 평균 4항목 비교표 (▲▼ 차이값 표시)
⑥ 액션 플랜
우선순위 1위/2위 개선 항목 + 달성 항목 유지 제안

발표 시 강조할 차별점 3가지
1
클러스터링 + 신체조건 이중 구조
클러스터링(행동 패턴)과 유사 사용자 매칭(신체 조건)을 결합해 "나와 체형이 비슷한 사람들이 어떻게 사는지" 맥락적 비교 가능
2
운동을 근력/유산소로 분리
단순 "운동량" 하나가 아닌, 근육증량/체중감량 목표에 따라 다른 운동 패턴을 군집 분류에 직접 반영
3
클러스터링 결과 → AI 코칭 직접 연계
수치만 보여주는 게 아닌, GPT가 클러스터 데이터를 받아 자연어 맞춤형 피드백 생성. 유사 사용자 대비 비교로 개인화

예상 질문 & 답변
Q. 가상 데이터 300명으로 클러스터링하면 실제 사용자에게 정확한가?
현재는 시스템 동작 검증 목적의 합성 데이터입니다. 실제 사용자가 쌓일수록 DB의 실제 사용자로 유사 사용자 매칭이 이루어져 정확도가 향상됩니다. 이 점을 논문 결론에 한계점으로 명시했습니다.
Q. LLM 없이 클러스터링만으로도 코칭 가능하지 않나?
가능합니다. 클러스터링이 핵심이고 LLM은 보조 역할입니다. 논문에서도 클러스터링에 집중하며, LLM은 자연어 피드백 생성 도구로 활용합니다.
Q. 앱을 실제로 사용해볼 수 있나?
Expo Go 앱 설치 후 링크로 접속 가능합니다. Railway 서버가 항상 켜져 있어 어디서나 사용 가능합니다.
Q. 식약처 API는 어떻게 활용되나?
"단백질 채우려면 뭐 먹어?" 같은 질문 시 실시간으로 식품영양성분 DB를 조회해 음식 추천 카드를 생성합니다. API 실패 시 하드코딩 폴백 값을 사용합니다.
Q. 점수는 어떻게 계산되나?
수분·단백질·운동 목표 달성률을 목표별 가중치로 합산합니다.
근육증량: 수분 25% + 단백질 35% + 근력 30% + 유산소 10%
체중감량: 수분 25% + 단백질 25% + 근력 15% + 유산소 35%
